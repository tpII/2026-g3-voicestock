# VoiceStock v0.5.0

These notes describe the version being prepared. `pyproject.toml` declares
`0.5.0`. A git tag and a GitHub Release have not been created.

The application revision cited by the 2026-11-04 hardware runs is
`c151db2c57b1fe3ece9c80baf76c38ca4ae8640a` on `develop`. The validation
closeout is
[v0.5.0 campaign report](../testing/raspberry-validation/v0.5.0-campaign-report.md).

## What this version does

- The Raspberry Pi records push-to-talk audio from BCM GPIO17 and a USB
  microphone (`voicestock_mic`) and writes a 16 kHz mono 16-bit WAV.
- `voicestock-pi` runs capture, the PC client, `PendingOperationFlow`, and
  the operator page in one process.
- The Pi can host the VoiceStock Wi-Fi cell (`192.168.50.1`) and an Arch
  PC can join it (`192.168.50.2`) without using that cell as the PC's
  Internet path. The accepted access-point process is hostapd
  ([ADR-0013](../decisions/0013-run-the-voicestock-access-point-with-hostapd.md)).
- The Pi HTTP client reaches `voicestock-pc-server` with text and with a
  WAV. Connection failure and response timeout are reported to the
  operator and leave no pending operation.
- The default PC audio handler is still the stub. It answers with
  `received_audio`. The Pi rejects that body and returns to idle with
  `El pedido no es una operación válida. Presioná el botón para intentar de nuevo.`
- `VOICESTOCK_AUDIO_PIPELINE=groq` sends the WAV to Groq Whisper
  (`whisper-large-v3-turbo`) and then to `openai/gpt-oss-20b`. One matching
  catalog product becomes one in-memory pending operation. The operator
  confirms or cancels it on `http://192.168.50.1:8000/`.
- The Pi validator checks the operation contract against the catalog
  before a pending operation is shown.

Hardware evidence for those paths is the Raspberry Pi campaign. Fifteen
active cases have a satisfactory latest technical result. TC-E2E-002 is
experimentally **FAILED** on one ambiguous command and is accepted for
this version anyway. See the campaign report. Older **FAILED** and
**BLOCKED** executions were not rewritten.

## Known limitations

- An ambiguous product description can still become a pending operation.
  On 2026-11-04, "Agregá dos paquetes de arroz Marolio" proposed Arroz
  Marolio 1 kg. The operator cancelled it. This is not fixed in v0.5.0.
  A future feature will handle it. Incident
  [INC-EX-TC-E2E-002-20261104-01-01](../testing/raspberry-validation/executions/INC-EX-TC-E2E-002-20261104-01-01.md)
  stays **OPEN**.
- Confirm and cancel do not change stock.
  `ProvisionalOperationExecutor` returns success and writes nothing.
- There is no accuracy guarantee for speech-to-text or for interpretation.
- A draft with more than one operation is outside this version.
- The historical access-point incidents from 2026-11-03 stay **OPEN**.
  They do not block this publication, and they are not marked fixed.
- No case in the campaign is **CLOSED_PASSED**. Formal review is still
  NOT_REVIEWED.

## Not in this version

- SQLite inventory updates.
- The withdrawn simulated cases TC-E2E-001 and TC-WEB-002.
- A deterministic PC contract fixture.
- A git tag or a GitHub Release. This file does not create them.
