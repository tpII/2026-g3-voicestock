## Scenario B — silent TCP peer

The VoiceStock HTTP server stayed stopped. The operator did not record
whether `ncat` or `nc` was installed, and did not run the `ncat` example.
A Python listener was started on Arch:

```python
import socket
import threading

def hold_connection(conn, addr):
    print(f"Accepted connection from {addr}", flush=True)
    with conn:
        threading.Event().wait(30)

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as server:
    server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    server.bind(("192.168.50.2", 8000))
    server.listen(5)
    print(
        "Silent TCP server listening on 192.168.50.2:8000",
        flush=True,
    )

    while True:
        conn, addr = server.accept()
        threading.Thread(
            target=hold_connection,
            args=(conn, addr),
            daemon=True,
        ).start()
```

It binds `192.168.50.2:8000`, accepts, prints the peer, holds the socket
for up to 30 seconds, and contains no send. That matches the silent-peer
behavior the criteria need. It is still a deviation from the version 1
example, which names `ncat`.
