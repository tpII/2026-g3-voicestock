## What happened

### Before the callback-based fix

The audio worker could remain blocked in a PortAudio
`RawInputStream.read()` call. Calling `stop()` or `abort()` did not
reliably unblock that call. `AudioCapture.stop()` then could not complete.

`vcgencmd get_throttled` later showed `0x50005`. That flag is recorded on
the parent execution as an environmental risk. It is not identified here
as the cause of the blocked read. The cause of the blocked read has not
been established.

### First fix iteration

A callback-driven backend was introduced:

```text
PortAudio callback
    |
    v
Bounded PCM queue
    |
    v
AudioCapture worker
    |
    v
WAV file
```

That iteration passed 38 automated audio tests. A physical execution still
failed. The worker remained blocked during `stream.close()`.

A Python traceback identified:

```text
sounddevice.py:1168 in close
sounddevice_backend.py:248 in close
capture.py:272 in _release_backend
capture.py:166 in _run
```

The line numbers describe the build that was running then. They are not
line numbers of commit `88a95d5`.

Further physical experiments, as reported by the operator:

| Experiment | Result |
| --- | --- |
| Standalone callback and PCM queue | Passed |
| Empty callback | Passed |
| PCM copying without a queue | Passed |
| Queue with a producer only | Passed |
| Queue with a producer and a consumer, worker closes the stream | Failed |
| Queue with a producer and a consumer, controller closes after the worker exits | Passed |

These rows are observations. They motivated a second lifecycle change.
They are not a proof of a single root cause.

### Second fix iteration

Production commits on `fix/audio-capture-stream-shutdown`:

- `022e2a6` — `fix(audio): separate worker termination from stream closure`
- `88a95d5` — `docs(audio): clarify stream lifecycle ownership and shutdown`

Full `022e2a6` hash:
`022e2a6d15d1e9ea4eb1391624cc5f27a58adbad`.

Full revision under the formal test:
`88a95d5754c72f419adb3461348161fa09f7ce8d`.

Corrected sequence:

```text
Controller requests backend.stop()
    |
    v
PCM consumer finishes
    |
    v
Controller joins the worker
    |
    v
Controller calls backend.close()
    |
    v
WAV validation and publication
```

The capture worker does not perform normal PortAudio stream closure.
That lifecycle is the one exercised by
[EX-TC-AUD-002-20261103-01](EX-TC-AUD-002-20261103-01.md). The five
measured runs completed. This incident does not repeat those numbers.

The product code remained on the fix branch. It had not been merged into
`develop` when the formal runs were recorded.
