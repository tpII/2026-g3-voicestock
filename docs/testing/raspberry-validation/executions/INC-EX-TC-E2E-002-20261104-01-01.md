## What happened

The spoken command was "Agregá dos paquetes de arroz Marolio." It did not
name a package weight. The written expectation is to reject the command
without a pending operation.

The system entered `phase=wait_confirmation`. `pending-operation` returned
HTTP 200. The pending operation was add, quantity 2, product Arroz Marolio
1 kg. The operation id was `0c9df2fe-da88-48e8-8d69-be4b3e8f5742`. The
recognized text was "Agrega dos paquetes de arroz malolio."

No root cause is claimed. The original `error.code` does not apply: the
response created a pending operation rather than a service rejection. The
response body was not archived.

## Criterion affected

- TC-E2E-002 criterion 8: the first attempt of N1 must create no pending
  operation.
- TC-E2E-002 criterion 9: that attempt must end in idle with a rejection
  sentence.

## Immediate recovery

The operator cancelled the proposed operation. The final state was `idle`,
with no pending operation, and `pending-operation` returned HTTP 204.
Cancellation does not close the incident.

## Follow-up

- Open question: why one of the matching presentations was selected. Do
  not treat a guess as the cause.
- [EX-TC-CON-001-20261104-01](EX-TC-CON-001-20261104-01.md) shows that
  `OperationValidator` returns `ambiguous_product` for name `Arroz`, brand
  `Marolio`, and presentation `null`. That does not show the contract N1
  actually submitted, and it does not close this incident. An upstream
  stage may have emitted a fully specified product. That remains a
  hypothesis.
- Expected later behavior: when more than one catalog presentation matches
  and the spoken command does not identify one of them, reject the command
  or ask for clarification. Do not select one silently.
- A later execution is required. It must cite this incident and repeat the
  N1 command. This incident does not implement that behavior.
- v0.5.0 acceptance: non-blocking known limitation, recorded only in
  [EX-TC-E2E-002-20261104-01](EX-TC-E2E-002-20261104-01.md). Confirmation
  lets the operator cancel a wrong proposal. It does not stop the operator
  from confirming one.
