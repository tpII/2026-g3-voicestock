## What happened

`sudo bash scripts/setup_pi_access_point.sh wlan0` created `voicestock-ap`
and deactivated the previous client connection. Activation failed:

```text
Error: Connection activation failed: 802.1X supplicant took too long to authenticate
```

NetworkManager logged `Hotspot network creation took too long, failing
activation` with reason `supplicant-timeout`. Kernel and supplicant text
included `brcmf_vif_set_mgmt_ie: vndr ie set error : -52`,
`nl80211: kernel reports: key setting validation failed`,
`Failed to initialize AP interface`, and `AP-DISABLED`. The Pi Wi-Fi
driver in this attempt was Broadcom `brcmfmac`.

A manual change, `802-11-wireless-security.pmf 1`, disabled PMF. The same
profile then activated at `192.168.50.1/24`, mode AP, WPA2-PSK, with no
gateway, no DNS, and no default route on `wlan0`. That manual activation
is not a pass of the script.

The Arch client, after the separate MAC restriction was removed, reached
`4way_handshake` and disconnected. The supplicant reported:

```text
WPA: IE in 3/4 msg does not match with IE in Beacon/ProbeResp
```

The kernel reason was `17=IE_DIFFERENT`.

Beacon/Probe Response RSN IE:

```text
30 14 01 00 00 0f ac 04 01 00 00 0f ac 04 01 00 00 0f ac 02 0c 00
```

Message 3/4 RSN IE:

```text
30 18 01 00 00 0f ac 04 01 00 00 0f ac 04 02 00 00 0f ac 02 00 0f ac 06 0c 00
```

The handshake element includes a second AKM suite, WPA-PSK-SHA256
(`00-0F-AC:6`), which the Beacon element does not advertise. The Beacon
element advertises one PSK AKM suite (`00-0F-AC:2`). Both sides used the
same `scripts/voicestock-network.conf` (SHA-256
`a2535edd865d5ec7fed1455b2b829c980d6048f0e857f74dd3d0a7d88547b187`), and
each profile was verified to store the PSK from its local file. The PSK
is not recorded here.

Disabling PMF on the Arch client did not make the handshake succeed.

A smartphone reported an incorrect password against the NetworkManager
access point. That report matches an authentication failure. It does not
show that the entered passphrase was wrong.

This record does not identify a conclusive defect inside the Broadcom
driver or firmware. The mismatch between the Beacon RSN element and the
RSN element in message 3/4 is the observed handshake failure.

A later `hostapd` process, with WPA2-PSK, CCMP, and PMF disabled,
authenticated the smartphone and the Arch USB client. That experiment is
evidence that this radio can complete a WPA2 handshake under a different
access-point service. It does not repair the NetworkManager path and it
does not close this incident.

## Criterion affected

Criteria 1 and 2 of TC-NET-001 fail because the prescribed script did not
leave a working access point. Criterion 3 also fails for the client, in
combination with
[INC-EX-TC-NET-001-20261103-02-02](INC-EX-TC-NET-001-20261103-02-02.md):
after the MAC restriction was cleared, the NetworkManager WPA2 handshake
still failed.

## Immediate recovery

The NetworkManager profile was later deactivated so `hostapd` could use
`wlan0`. `wlan0` was set unmanaged for that experiment. Ethernet `eth0`
stayed at `192.168.1.100/24` for SSH. No repository script was edited.
The temporary `hostapd` configuration was not left as the product setup.

## Follow-up

- Open questions: which component inserts the extra WPA-PSK-SHA256 AKM
  suite into message 3/4 is not established. PMF disabled is sufficient
  to activate the NetworkManager AP and is not sufficient for the Arch
  client to finish the 4-way handshake.
- The `hostapd` result is a reason to evaluate a dedicated access-point
  service. The evaluation note is
  [hostapd-evaluation.md](../hostapd-evaluation.md). Any implementation
  change needs a new execution under an adopted procedure. Procedure
  version 1 is unchanged.
- TC-NET-002 and TC-NET-003 stay unexecuted.
- A new TC-NET-001 execution is required after the access-point
  implementation is decided. This incident stays open until that
  execution passes the prescribed setup without this handshake failure.

Do not mark the parent execution **CLOSED_PASSED** while this incident is
OPEN. It fails the case.
