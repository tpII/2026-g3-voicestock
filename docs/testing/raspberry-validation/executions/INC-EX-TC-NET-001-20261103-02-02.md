## What happened

The PC setup script failed with:

```text
The MACs of the device and the connection didn't match.
```

The dedicated VoiceStock interface was `wlp0s20f0u4` on a TP-Link
TL-WN823N v2/v3 (Realtek RTL8192EU, driver `rtl8xxxu`).

Investigation on that machine distinguished two addresses:

- Permanent USB MAC: `c0:06:c3:e1:1d:31`
- The interface address in use: a temporary locally administered MAC.
  The temporary value itself was NOT RECORDED.

`scripts/setup_pc_voicestock_wifi.sh` reads the current address from
`/sys/class/net/<interface>/address` and writes it to
`802-11-wireless.mac-address`. NetworkManager treats that property as a
match against the device's permanent MAC, not against a temporary
interface address. The script therefore stored a restriction the device
did not satisfy.

The checkout SHA on the PC was NOT RECORDED. The behavior matches the
script on `origin/develop` at documentation time (`55d6e59`), which still
assigns that property from `interface_mac`. That tip is not claimed as
the PC revision under test.

The operator removed the restriction:

```bash
sudo nmcli connection modify voicestock-client 802-11-wireless.mac-address ""
```

The MAC error did not recur. The WPA2 handshake to the NetworkManager
access point still failed, which is
[INC-EX-TC-NET-001-20261103-02-01](INC-EX-TC-NET-001-20261103-02-01.md).
Clearing the property did not produce criterion 3.

During the later `hostapd` diagnostic, the Arch station that authenticated
used `c0:06:c3:e1:1d:31`. That observation is not a pass of the PC script.

## Criterion affected

Criterion 3 of TC-NET-001. The prescribed PC script did not leave
`voicestock-client` active on the dedicated interface.

## Immediate recovery

The operator cleared `802-11-wireless.mac-address` on the existing
profile. The script in the repository was not changed. No passphrase was
rewritten by that command.

## Follow-up

- The script must not write a transient sysfs MAC into
  `802-11-wireless.mac-address` when that property is a permanent-MAC
  match. Interface binding belongs in `connection.interface-name`, which
  the script already sets.
- A regression execution has to run the corrected script on
  `wlp0s20f0u4` while the interface holds a locally administered address
  and show that the profile still activates.
- This incident does not close when the handshake incident is fixed.
  Both can fail the same future run if only one is corrected.

Do not mark the parent execution **CLOSED_PASSED** while this incident is
OPEN. It fails criterion 3.
