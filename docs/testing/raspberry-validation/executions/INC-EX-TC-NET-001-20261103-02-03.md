## What happened

Attempt 02 did not exit on this check. The PC script exited on the MAC
restriction in
[INC-EX-TC-NET-001-20261103-02-02](INC-EX-TC-NET-001-20261103-02-02.md).
`require_managed` runs before the profile is written. On this run the
dedicated interface was not in a state the `10*` pattern rejects, so the
latent pattern was not the observed failure.

The Pi correction is `device_state_is_unmanaged` in
`scripts/setup_pi_access_point.sh`: unmanaged is numeric code `10` only,
so `100 (connected)` is managed. The access-point script's progress in
attempt 02 is the behavioral check of that correction. The board SHA was
not recorded.

`scripts/setup_pc_voicestock_wifi.sh` on the inspected `develop` tip still
contains:

```bash
case "$state" in
  10* | unmanaged* | Unmanaged*)
    error "Wi-Fi interface ${interface_name} is not managed by NetworkManager."
    ;;
esac
```

In Bash, `10*` matches every string that begins with `10`, including
`100 (connected)` and `110 (deactivating)`. A future PC run against a
connected VoiceStock interface can stop with the same false unmanaged
error attempt 01 recorded on the Pi.

This documentation task does not change the script.
