# VoiceStock v0.5.0 — Raspberry Pi validation closeout

This note is the source a later Taller de Proyecto II report can cite.
Measurements and logs stay in the execution files. This page does not
repeat them.

Campaign testing for v0.5.0 is closed. No further execution is planned for
this version. The release decision is `ACCEPTED_WITH_KNOWN_LIMITATIONS`.
That decision is not a **CLOSED_PASSED** mark on any case. Historical
**FAILED** and **BLOCKED** executions stay as written.

Application revision exercised on 2026-11-04: `develop` at
`c151db2c57b1fe3ece9c80baf76c38ca4ae8640a`. The package field in
`pyproject.toml` is `0.5.0`. No git tag and no GitHub Release exist
for v0.5.0.

## Objective and scope

Show that the Raspberry Pi subsystem runs on the project hardware and that
GPIO, audio, the isolated Wi-Fi cell, HTTP, contract validation, pending
operation errors, and one real Groq voice-to-web cycle integrate.

Sixteen active cases were executed. TC-WEB-002 and TC-E2E-001 were
withdrawn before any execution. Withdrawal is not a pass. The case list is
the [campaign README](README.md#what-this-campaign-covers).

Out of scope, and not claimed: a speech-to-text accuracy guarantee, an
interpretation accuracy guarantee, more than one operation per utterance,
and inventory persistence. Confirm and cancel call
`ProvisionalOperationExecutor`, which reports success and writes nothing.

## Method

Each case has a written procedure, an execution id, and a technical
result. **PASSED_PENDING_DOCUMENTATION** means the observed criteria of
that run were met and formal review or archived evidence is still open.
It is not **CLOSED_PASSED**. A later passing run does not rewrite an
earlier **FAILED** or **BLOCKED** file.

The release decision is a separate sentence from the experimental status.

## Problems and what was done

- Early GPIO and push-to-talk runs failed or blocked (constructor, muted
  microphone, unmet prerequisite, cleanup not verified). Later runs on
  2026-11-04 met the written checks. The old files were not regraded.
- Access-point setup failed twice on procedure version 1 (`hostapd` and
  WPA2). Procedure version 2 then brought the cell up. The three network
  incidents from the failed attempts stay **OPEN**. The team accepts
  publication with those incidents still open. They are not marked fixed.
- TC-E2E-001 and TC-WEB-002 needed a deterministic contract fixture that
  was never built. They were withdrawn. TC-FLOW-001 procedure version 2
  tests error handling instead of that fixture. Procedure version 1 was
  not executed.
- N1, "Agregá dos paquetes de arroz Marolio", created a pending add of
  Arroz Marolio 1 kg. The operator cancelled it. The experimental result
  stays **FAILED**. The team accepts it for v0.5.0 and will not fix
  ambiguous products in this version.

## Known limitations

- Ambiguous catalog matches can become a pending operation. Record:
  [INC-EX-TC-E2E-002-20261104-01-01](executions/INC-EX-TC-E2E-002-20261104-01-01.md),
  status **OPEN**, disposition `ACCEPTED_WITH_KNOWN_LIMITATIONS`.
- Inventory is not persisted.
- No production accuracy claim for Whisper or for `openai/gpt-oss-20b`.
- Reviews are NOT_REVIEWED. Evidence hashes in several runs were not
  recomputed in the documentation workspace. WAV files are not in git.
- Several latency budgets remain **TO BE DEFINED**. FLOW release-to-idle
  time was not measured.

## Conclusion

VoiceStock v0.5.0, on the recorded hardware, captures a button-controlled
WAV, ships it across the isolated cell, and can turn one Groq
interpretation into a single in-memory pending operation that the operator
confirms or cancels. The same runtime returns to idle on a stub contract
rejection, a refused connection, and a withheld HTTP response. The version
is accepted with the N1 limitation and without inventory persistence. It
is not a claim that every historical execution passed, and it is not a
**CLOSED_PASSED** campaign.
